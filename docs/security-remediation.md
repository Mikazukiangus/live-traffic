## Regression and verification scope

New auth regressions failed on the baseline, then passed after remediation. The negative image regressions, framing policy, workflow requirements and local permission regression were likewise checked before their fixes. Existing tests were retained; arbitrary-byte camera fixtures were replaced by valid JPEG fixtures with byte/length assertions preserved or strengthened.

TypeScript (`npm run lint`) and the existing transport audit are run for each category commit, followed by the existing suite. Loopback HTTP fixtures require execution outside the filesystem/network sandbox; those requests are local only. Auth tests use in-memory SQLite and synthetic identities, not the Neon database. Provider calls remain mocked. Wrapper/installer unit tests use local fixtures; the added scanner integration tests invoke the actual checksum-verified Gitleaks binary with generated, non-provider-issued canaries. Installer tests check checksum rejection before binary execution and exact-version enforcement.

Gitleaks 8.30.1 was downloaded from its official GitHub release and passed its release-manifest SHA-256/version checks. Seven history candidates were reviewed as synthetic or deliberately invalid test fixtures and are exempted only by exact historical commit/file/rule/line fingerprints. No real credential was confirmed exposed. This is a bounded scan, not proof that every possible secret format was detected. Registry metadata and the GitHub-reviewed Zod advisory were checked; the patched release integrity matches the lockfile. No Vercel API, live provider, real database or production request was made. Existing unrelated untracked files remain untouched.

Final result: **372 tests passed, zero failed**; type checking, transport audit, private-env permission check and the production build all passed. The existing suite was rerun after category commits. The real scanner integration checks pass, the Git-history/build scans pass under the reviewed policy, the dependency audit reports zero advisories and the pre-commit hook is active. The category commits preserve the existing required `checks` job and Git-based Vercel deployment gate; no additional deployment token or release workflow was introduced.

## Compatibility and rollout

- This branch is for explicit review/merge. Existing auth enablement flags are preserved; no production login is enabled.
- Active/legacy sessions older than 24 hours require another login. The account budget also counts correct sign-ins, so ten sign-ins per account per 15 minutes is the effective cross-IP cap. This is an attempt budget, not progressive failure-only lockout.
- Failed logout now produces a retryable failure instead of claiming revocation. Keep the user's ability to retry; do not display logout success on 503.
- The app can no longer be embedded in an iframe after deployment. Existing camera images, scripts and WASM worker policy are otherwise preserved. General CSP tightening remains deferred; use report-only observation before that separate change.
- The proxy accepts JPEGs only, matching its existing response contract. Oversized, truncated, unsupported or incorrectly labelled non-image responses become safe unavailable states. Validate official live images later under explicit network authorization.
- Gitleaks is a separate development/CI tool, not an application dependency. After local hook activation, missing/wrong-version Gitleaks blocks nonempty code commits. Follow SECURITY.md to install the pinned tool only with authorized network access. Hook configuration is local to this clone; contributors must activate their own hooks.
